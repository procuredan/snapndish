# Talk It function-output protocol correction — Stage 1B

## Pre-change record — 2026-10-20

- **Approved source and control:** Exact base `c3ded7a864685a4e03a54082f8f0cb51acf24827`; recorded isolated staging Worker `aee452b1-1fbf-4c3d-b074-9ea589dfb17d`. Reverify the active version and rollback eligibility before release.
- **Existing system and authority:** The Worker conditionally accepts a meal or cooking proposal against the current D1 customer/session revisions. The browser gives the Realtime provider the actual backend result, then schedules one same-origin spoken continuation after an output-item acknowledgment. The browser's explicit context includes only accepted customer inputs, verified response outputs and acknowledged tool outputs.
- **Observed defect:** In the owner's October 20 microphone session, the backend accepted a complete meal and Shopping, but the client sent a custom 37-character `item.id` with `conversation.item.create`. The provider returned `string_above_max_length` for `item.id`; the output was not acknowledged, no continuation was requested, and Talk It closed. The private incident transcript and event timeline remain in ignored local evidence, outside the repository.
- **Authorized extension:** Omit the optional outgoing item ID. Retain the outgoing event ID, provider call ID, originating input, response owner, actual backend result and existing continuation order. Treat only a provider-returned function-output item with matching ID/type/call/result/owner as acknowledgment. Keep duplicate and stale responses single-use.
- **Regression surface:** Wrong, duplicate and late acknowledgments; accepted and rejected meal state; duplicate Shopping/history; currentness; empty input and genuine interruption; context ordering; provider error handling; browser reload and voice restart.
- **Proof plan:** Full D1-compatible tests, enabled Chrome lifecycle suite, exact-source GitHub CI, staging Worker/Access/bindings/ledger/recovery review, isolated deployment, rendered and real microphone customer choice → accepted package → provider output acknowledgment → spoken continuation → further customer speech. An unsimulated microphone run is required for physical voice acceptance.
- **Recovery:** No migration or D1 mutation is introduced. Verify a fresh isolated staging D1 Time Travel point before deployment. Routine code rollback is to the verified pre-change Worker only; do not restore D1 as part of that rollback. Stage 1A, production and Milestone 2 are outside scope.

## Local implementation and verification

- **Client change:** `live-lab/ui.mjs` sends a function-call output with `event_id`, `call_id` and the Worker result, omitting `item.id`. It retains the pending event ID and exact output while waiting for the provider item. The returned item must match the pending call/result and response owner before its provider ID enters explicit context; the existing scheduler then applies input currentness before one continuation.
- **Provider contract:** The [Realtime client event specification](https://developers.openai.com/api/reference/resources/realtime/client-events) makes function-output `item.id` optional and describes provider item events or an error after item creation. The provider item contains `id`, `type`, `call_id` and `output`; success does not echo the outgoing event ID as the returned item ID. The event ID remains in diagnostics and provider errors, while the call/result/response owner establish successful association.
- **VERIFIED local:** `npm test` passed 72/72 with 11 opt-in browser tests skipped. `SNAP_BROWSER_TEST=1 npm test` passed all 83/83. The Chrome fixtures now use a provider-created output ID. They prove no continuation before acknowledgment, provider ID in explicit context, one continuation after a valid acknowledgment, no release from an unrelated item, duplicate acknowledgment, wrong call or wrong result, no stale continuation after a newer customer revision, and no repeated meal/Shopping mutation after a provider error. Existing D1-compatible tests prove accepted package before speech, idempotent replay, rejected proposal preservation, customer isolation, recipe history, Shopping edits, empty input and response ownership. `npm run preflight`, client/Worker syntax checks and `git diff --check` passed.
- **NOT VERIFIED yet:** Exact-source GitHub CI, current Cloudflare preflight, staged provider acknowledgment, natural spoken continuation and real microphone quality. The separately authorized silence/cough/intentional interruption comparison has not been run.
