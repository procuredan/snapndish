## Provider contract gate

**VERIFIED in the current official Realtime API specification:** `response.create` accepts `input` item references, `metadata`, and `conversation:"auto"` in one request shape. The guide explicitly shows `input:[]` with output inserted in the default conversation. Response creation/done events contain the response metadata and ID. Semantic VAD exposes independent `create_response` and `interrupt_response` fields; interruption targets an ongoing response written to the default conversation. Function-call output is linked by `call_id` and followed by another `response.create`. See [client events](https://developers.openai.com/api/reference/resources/realtime/client-events) and [conversation guide](https://developers.openai.com/api/docs/guides/realtime-conversations).

**Important context constraint:** An explicit `input` array replaces default input context for that response. A candidate must reference all intended in-session context items in order, including tool output. Provider behavior for the exact combined request remains a live staging verification gate; documentation establishes the contract before implementation, but cannot substitute for the physical microphone acceptance.
